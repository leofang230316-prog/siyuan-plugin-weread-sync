- **竞品 siyuan-plugin-weread（mdzz2048）已停更两年半**（最后发版 2023-11-07 v1.2.4，最后提交 2024-01-23）。覆盖式更新是其最大痛点，本插件的增量+本地编辑保护是核心差异化。

- **最大技术风险（CORS）已解除**：思源内核提供 `POST /api/network/forwardProxy`，是完整可控 HTTP 客户端。可注入任意 headers、能读响应头 Set-Cookie、支持 base64 接收二进制。所有外部请求由 Go 后端发出，浏览器同源策略不适用。约束：需 CheckAuth + **CheckAdminRole**（Docker 多用户非管理员不可用），有 SSRF 防护仅放行公网。

## v1.0.2 修复：微信读书登录接口变更（实测确认）

- 原用的 `/web/login/getuid`、`/web/login/getinfo` 已失效（404）。
- **实测确认的新接口**（从 weread.qq.com 前端 JS 提取 + 直接请求验证）：
  - 获取 uid：`GET https://weread.qq.com/api/auth/getLoginUid` → `{"uid":"<uuid>"}`
  - 轮询：`GET https://weread.qq.com/api/auth/getLoginInfo?uid=<uid>&otp=` —— **60 秒长轮询**，未扫码时连接挂起，超时属正常现象应判为继续等待
  - 成功返回：`{succeed:true, accessToken, webLoginVid}`，其中 **accessToken 即 wr_skey、webLoginVid 即 wr_vid**，Cookie 鉴权体系不变
  - `logicCode`：LOGIN_TIMEOUT / NEED_OTP / OTP_EXPIRED / OTP_NOT_MATCH
  - 二维码内容不变：`https://weread.qq.com/web/confirm?uid=<uid>`
- **不存在 token 续期接口**，凭证过期只能重新扫码登录。
- 另有微信开放平台 OAuth 通道（appid `wxd80042f4d6cfc9a6`、scope `snsapi_login`、`POST /api/login/wxCode`），但二维码由 `wxLogin.js` 在 iframe 渲染、code 只回调给微信读书自有域名，插件内无法取得 code，未采用。
- 数据接口 `i.weread.qq.com/*`（shelf/sync、user/notebooks、bookmarklist、review/list、book/info）**全部仍有效**（未登录返回 401 而非 404）。
- **排查方法（可复用，比浏览器抓包轻量）**：拉首页 HTML → 正则提取 Nuxt JS 地址 → 下载 JS 搜接口字符串 → 用 urllib 直接实测。无需 Playwright/Chromium。
- git commit `045eb05`，tag `v1.0.2`。

## v1.0.5 修复：同步事务 panic、笔记为空、封面下载、/ 引用命令

- 用户反馈四个问题：
  1. 同步中思源报 `transaction panic: runtime error: invalid memory address or nil pointer dereference`；
  2. 下载的笔记内容为空；
  3. 书本封面未下载同步；
  4. 无法用 `/` 引用笔记内容。

### 问题 1：transaction panic
- 根因推断：多本书并发创建文档/插入块，思源 SQLite 事务冲突引发 Go 端 nil pointer panic。
- 修复：`src/core/sync.ts` 取消并发 worker pool，改为**顺序处理单本书**；书与书之间保留请求间隔喘息；同时给所有块操作增加空值/空内容校验。
- `DEFAULT_SETTINGS.concurrency` 改为 1，设置文案说明当前强制顺序。

### 问题 2：笔记内容为空
- 对齐 mcp-server-weread 的 web 端调用：
  - `chapterInfos` 请求体从 `{bookIds:[], synckeys:[0]}` 改为 `{bookIds:[bookId]}`。
  - `review/list` 参数从 `listType=11&mine=1&synckey=0&listMode=0` 改为 `listType=4&maxIdx=0&count=0&listMode=2&syncKey=0`。
- `checkWebErr` 同时识别 `errCode` 与 `errcode`（微信读书 web 接口使用小写）。
- `dataHeaders` 拆分为 `getHeaders` / `postHeaders`，GET 请求不再带 `Content-Type`。
- 同步时跳过渲染后内容为空的笔记，避免插入空块。

### 问题 3：封面下载
- `renderBookMarkdown` 新增可选 `coverAssetPath` 参数，在书籍文档顶部插入封面图片。
- `syncOneBook` 在新文档创建前调用 `fetchCoverDataUrl`，通过 `getCoverBase64` 拉取封面 base64，转换为 `data:image/jpeg;base64,...` 内嵌到文档。
- 选择 data URL 而非写入 `assets`：思源 `/api/file/putFile` 要求 multipart 上传，插件当前 `fetchSyncPost` 走 JSON，直接写文件不可靠；data URL 自包含、无额外文件依赖。
- `getCoverBase64` 增加 `Referer: https://weread.qq.com/web/shelf` 请求头，提高图片服务器放行概率。
- 设置文案更新：封面现在会写入笔记文档并显示在面板。

### 问题 4：/ 斜杠命令
- `registerSlash` 回调增加兜底：若 `nodeElement` 没有 `data-node-id`，取 `protyle` 当前选中块；仍无则提示失败。
- `SearchDialog.insert` 增加 `nodeId` 校验、`insertBlock` 返回值校验与错误提示。
- `openSearch` 入参改为 `HTMLElement | null`，无有效块时直接提示。

### 其他
- `src/api/siyuan.ts` 的 `putFile` 增加可选 `isDir` 参数，支持创建目录。
- 版本 `1.0.5`，package.zip 45KB，`tsc --noEmit` 通过。
- 未验证项：真实登录态下 web 数据接口是否仍返回空内容，需用户安装后实测。

## v1.0.7 修复：真正的根因是 zh_CN.json 语法错误（漏逗号）

- 用户重装 v1.0.6 后仍报 `Cannot read properties of undefined (reading 'logout')` / `reading 'title')`，Dock 与设置面板初始化即崩，名字仍不显示。
- **查思源内核源码确认（非猜测）**：`kernel/model/plugin.go` 的 `loadCode` 用 `gulu.JSON.UnmarshalJSON(data, &petal.I18n)` 直接把 `i18n/zh_CN.json` 解析成 `map[string]any`，**不展平**、且**任一语言文件 JSON 语法错误→整个 i18n 解析失败、`petal.I18n` 保持空 map**。`plugin.json` 的 `i18n` 字段内核根本不读（只用于集市展示）。
- **真实根因**：`src/i18n/zh_CN.json` 第 119 行 `coverDesc` 值末尾**漏了逗号**，导致 `{"coverDesc": "...<br>" "clearCover": ...}` 非法 JSON，整文件 parse 失败 → `this.i18n={}` → 所有嵌套键 undefined。en_US.json 一直合法。
- 验证：用 `node -e "JSON.parse(fs.readFileSync(...))"` 对两个文件校验，zh_CN 报 `Expected ',' or '}' at position 3210 (line 119)`；修复逗号后两个文件均 OK。
- 修复：补全 zh_CN.json 逗号；重新 `rm -rf dist && npm run build`；已用脚本确认 package.zip 内 `i18n/zh_CN.json` 合法且含 `pluginName`/`login` 嵌套键。
- 教训：v1.0.6 把根因误判为「缺 i18n 字段 + onLayoutReady 过早」，那两个改动是好的实践但非真正病根。**改完 i18n 必须 JSON 校验**（已写入 MEMORY.md 红线）。
- 版本 `1.0.7`，commit `e067417`，tag `v1.0.7`。
