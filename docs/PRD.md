## 一、项目概述

### 1.1 目标

开发一款思源笔记插件，将用户微信读书账号下的全部书籍及其划线、想法、阅读进度、章节目录同步到思源笔记，并支持在思源内检索、浏览与调用这些笔记。

### 1.2 核心价值主张

与现有社区插件的本质差异在于**保护用户在思源侧的二次创作**：

- 现有插件采用覆盖式更新，明确要求用户"不要在同步的文件里修改内容"；
- 本插件采用增量追加 + 三方比对策略，用户在思源中做的任何编辑都不会被同步覆盖；
- 冲突时双版本共存并各自标注时间戳，远端删除时本地保留并标注，绝不静默丢数据。

### 1.3 版本范围（1.0.0）

**纳入范围**：安装与入口、扫码登录、书籍与笔记同步、思源内检索与插入、增量与冲突处理、移动端只读浏览。

**明确排除**：章节正文原文抓取（涉及内容解密，体积与合规风险过高）、热门划线与他人书评（易污染笔记库）、多账号切换、写回微信读书（反向同步）。

## 三、竞品分析

### 3.1 mdzz2048/siyuan-plugin-weread

**现状**：最后一次发版 2023-11-07（v1.2.4），最后一次提交 2024-01-23，已停更约两年半。作者自述"处于 Demo 阶段，还有很多 bug"。

**功能**：书籍元数据导入、划线与笔记同步、热门标注、扫码登录、自动刷新 Cookie、自定义模板。

**已知缺陷（即我们的机会点）**：

| 竞品问题 | 本插件对策 |
|---|---|
| 覆盖式更新，README 明令"请不要在同步的文件里修改内容" | 增量追加 + 三方比对，本地编辑零覆盖 |
| 部分导入时未选中的笔记不导入，导致块 ID 失效、已有块引用断裂 | 全量 ID 锚定，块 ID 一经生成永久稳定 |
| 导入顺序不按章节（先标注后想法） | 按章节目录树组织，划线与想法归并到所属章节 |
| 常见 `block not found`，需重建索引 | 同步前校验文档与块存在性，脏 ID 自动修复 |
| 点击按钮、打开设置卡顿（同步式 Cookie 校验） | 后台异步校验 + 状态缓存 |
| 无写作时调用笔记的能力 | 斜杠命令 + Dock 面板双通道插入 |

### 3.2 Glaube-TY/siyuan-douban

含 WeRead 同步能力，走 API Key 模式，功能覆盖豆瓣导入、数据库、模板、公众号内容。功能广度远超本插件，但定位是"阅读管理全流程"。本插件不做功能对标，专注"笔记同步 + 思源内调用"单点做深。

## 四、技术可行性验证结论

**验证方式**：拉取思源 v3.8.1 内核源码（`kernel/api/network.go`、`kernel/api/router.go`、`app/src/plugin/index.ts`）逐一核对，非依赖网络资料推断。

### 4.1 关键发现：跨域问题不存在

思源内核提供 **`POST /api/network/forwardProxy`** 接口，是一个完全可控的 HTTP 客户端。所有对 `weread.qq.com` 的请求均由思源内核（Go 后端）发出，浏览器同源策略完全不适用。

请求参数：

| 参数 | 类型 | 说明 |
|---|---|---|
| `url` | string（必填） | 目标地址，仅允许 http/https |
| `method` | string | 默认 `POST`，可指定任意方法 |
| `headers` | array | 每项为 `map[string]any`，可注入 Cookie 等任意请求头 |
| `payload` | any | 请求体 |
| `payloadEncoding` | string | json / text / base64 / hex 等 |
| `responseEncoding` | string | 默认 text，设 base64 可接收二进制 |
| `timeout` | number | 毫秒，默认 7000 |
| `redirect` | bool | 传 false 时禁用重定向跟随 |

返回数据：

```
{ code, msg, data: { url, status, contentType, body, bodyEncoding, headers, elapsed } }
```

**对项目的三个决定性意义**：

1. **扫码登录可行**：响应头 `data.headers` 完整返回，可读取 `Set-Cookie` 拿到 `wr_vid` / `wr_skey` / `wr_rt` 登录凭证。
2. **Cookie 完全自主**：通过 `headers` 注入，不依赖浏览器 Cookie jar，登录态由插件自己管理。
3. **封面可下载**：`responseEncoding: "base64"` 取二进制，再经 `/api/file/putFile` 落盘。

**两个必须遵守的约束**：

- 该接口注册了 `model.CheckAuth` + **`model.CheckAdminRole`**，非管理员角色会被拒绝。Docker 多用户部署下普通用户不可用，需在使用说明中注明。
- 内核使用 `util.SSRFSafeDialer` 做 SSRF 防护，仅放行公网地址。`weread.qq.com` 为公网域名，不受影响。

### 4.2 思源内核 API 可用性核对

全部通过，均已在 `router.go` 中确认注册：

| 用途 | 接口 | 状态 |
|---|---|---|
| 创建笔记本 | `/api/notebook/createNotebook` | 可用 |
| 创建文档 | `/api/filetree/createDocWithMd` | 可用 |
| 读取文档 | `/api/filetree/getDoc` | 可用 |
| SQL 查询（反查块属性） | `/api/query/sql` | 可用 |
| 追加块 | `/api/block/appendBlock` | 可用 |
| 插入块 | `/api/block/insertBlock` | 可用 |
| 更新块 | `/api/block/updateBlock` | 可用 |
| 读取块 Markdown | `/api/block/getBlockKramdown` | 可用 |
| 设置块属性 | `/api/attr/setBlockAttrs` | 可用 |

### 4.3 前端插件 API 核对

已在 `app/src/plugin/index.ts` 中确认：

### 7.2 块属性定义

| `weread-ts` | 微信读书的笔记时间（毫秒时间戳），展示用 |
| `weread-type` | `underline`（划线）/ `review`（想法） |
| `weread-chapter` | 所属章节标题 |
| `weread-book` | 所属书籍 bookId |
| `weread-deleted` | 远端已删除标记，值为删除发现时间 |

### 7.3 插件本地存储

| 存储键 | 内容 |
|---|---|
| `credentials` | 登录凭证（wr_vid / wr_skey / wr_rt / wr_gid 等），脱敏存储 |
| `settings` | 用户设置项 |
| `shelf-cache` | 书架全量缓存（书籍元数据） |

封面缓存路径：`data/storage/petal/siyuan-plugin-weread-sync/covers/{bookId}.jpg`，经 `/api/file/putFile` 写入。

## 八、同步合并算法

### 8.1 三方比对

每次同步对每条远端笔记执行如下判定，输入为：本地块文本、上次同步快照、当前远端原文。

| 状态 | 判定条件 | 处理 |
|---|---|---|
| 新增 | 本地无对应 `weread-bmid` | 追加块，写入全部属性 |
| 静默更新 | 有 bmid，本地文本 == 快照，远端文本 != 快照 | `updateBlock` 更新内容，刷新 hash 与时间戳 |
| 冲突 | 有 bmid，本地文本 != 快照，远端文本 != 快照 | 保留本地块不动，追加远端新版块，标注「微信读书更新版」+ 时间戳 |
| 远端已删 | 本地有 bmid，远端列表已无 | 保留本地块，写入 `weread-deleted` 属性，文本尾部追加「已在微信读书删除」 |
| 无变化 | 本地文本 == 快照 == 远端文本 | 跳过 |

### 8.2 幂等性

同一份数据在未发生任何变更的情况下重复同步，不得产生任何新块、任何内容改动。此为验收硬指标。

### 8.3 限流与稳定性

| 策略 | 参数 |
|---|---|
| 并发数 | 默认 2，设置中可调（1-5） |
| 请求间隔 | 默认 300ms，叠加 0-200ms 随机抖动 |
| 单次超时 | 默认 15s（forwardProxy 默认 7s，本插件显式放宽） |
| 重试 | 指数退避 1s / 2s / 4s，单本最多 3 次 |
| 连续失败熔断 | 连续 10 本失败即中止整轮同步，保留进度 |
| 断点续传 | 每完成一本即写入 `sync-progress`，中断后从下一本继续 |

## 十一、风险与应对

| # | 风险 | 等级 | 应对措施 |
|---|---|---|---|
| R1 | 微信读书接口为非官方，随时可能变更或加严风控 | 高 | 接口层抽象；M0 先验证；失败时给出明确错误提示而非静默失败；提供 Cookie 手动兜底 |
| R2 | Cookie 过期（wr_skey 有有效期） | 中 | 用 wr_rt 自动续期；续期失败引导重新扫码；不清空已同步数据 |
| R3 | `forwardProxy` 要求管理员角色 | 中 | 文档中注明 Docker 多用户场景限制；启动时检测权限并提示 |
| R4 | 大量书籍同步耗时过长 | 中 | 快速模式、并发与限速、断点续传、进度可中断 |
| R5 | 本地数据体积增长（封面缓存、sync-state） | 低 | 封面缓存可开关与清理；sync-state 定期瘦身 |
| R6 | 合并逻辑边界情况（用户手动删除了块、文档被移出笔记本） | 中 | 同步前校验文档与块存在性；文档丢失时按 bookId 重建并明确告知 |
| R7 | 集市上架时仓库名与 name 必须一致，改名成本高 | 低 | 名称已在需求阶段锁定为 siyuan-plugin-weread-sync |

## 十三、验收标准

1. 插件可通过本地安装方式安装并启用，顶栏图标与 Dock 面板正常显示。
2. 扫码可完成登录，重启思源后登录态保持。
3. 全量同步后，书籍数量与微信读书书架一致，元数据字段完整。
4. 所有笔记均带微信读书笔记时间戳，按章节归组。
5. 连续执行两次同步（期间无任何变更），文档内容完全一致，无重复块产生。
6. 在思源中修改某条笔记后再次同步，该修改被完整保留。
7. 在微信读书修改某条笔记后同步，本地未编辑的块被更新，已编辑的块保留且新增「微信读书更新版」。
8. 在微信读书删除某条笔记后同步，本地块保留并标注「已在微信读书删除」。
9. 同步中途强制关闭思源，重启后可从断点继续，已有文档无损坏。
10. 斜杠命令可搜到笔记并插入块引用，微信读书侧更新后引用内容同步跟随。
11. 移动端可正常浏览书架与笔记，插入与同步入口不可见。
12. 打包产物符合思源集市全部规范（含 icon.png、preview.png、i18n、README）。
